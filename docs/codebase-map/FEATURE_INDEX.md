### Ownership cautions

- ChatSession is declared in the large ChatView.swift file, while transcript data and durable writes live in model/store/database files. Search for the specific method or type inside the owner before reading the whole file.
- Prompt composition and tool execution are different boundaries. SystemPromptComposer prepares the prompt and schemas; ToolRegistry and the request-scoped execution context enforce whether a call may run.
- Local tool-call parsing is owned by the pinned upstream vmlx-swift `BatchEngine`, not by an Osaurus source file. Osaurus passes tool schemas through ModelRuntime/MLXBatchAdapter and maps the emitted call through GenerationEventMapper and ResponsesGenerationEvent.
- UI state is not proof of effective runtime state. For a setting or feature gate, trace the UI through its persisted store to the composed request and the service that consumes it.
- Plugin, MCP, sandbox plugin, and skill lifecycles share some registry surfaces but have distinct managers, permissions, and tests. Do not assume they are interchangeable.
