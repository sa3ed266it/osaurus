# Change Router

Use this page to locate the likely owner, then confirm the path in source. It is a routing aid, not permission to assume behavior from a file name.

## Investigation rules

1. Start at [README.md](README.md), then find the feature in [FEATURE_INDEX.md](FEATURE_INDEX.md).
2. Read the owning function/type and the nearest relevant test first.
3. Follow a dependency only when the requested behavior crosses into it: for example, a visible setting that changes an effective request, or a declared tool that fails execution.
4. Keep UI-only work within the view and layout owners when no shared state or request behavior is involved. Treat persisted settings, prompts, tool schemas, provider routing, and runtime state as shared-contract work.
5. Reuse the existing manager, service, registry, or component that owns the behavior. Do not create a parallel implementation because a neighboring feature has a similar name.
6. For user-facing settings, preserve the root [AGENTS.md](../../AGENTS.md) Settings catalog requirements: update SettingsSearchIndex, the control anchor, guide path, and self-find probe.
7. Use [TEST_MAP.md](TEST_MAP.md) for targeted validation. Broaden only when the relevant tests or call chain identify another affected surface.

## Local model tool-call decision tree

Identify the first broken boundary and follow only that path. A request can have a valid schema but still fail later in local parsing, event transport, or execution.

**A. Tools are absent from the request.** Inspect [SystemPromptComposer.swift](../../Packages/OsaurusCore/Services/Chat/SystemPromptComposer.swift) for `resolveTools`; follow gate inputs in [AgentConfigSnapshot.swift](../../Packages/OsaurusCore/Services/Chat/AgentConfigSnapshot.swift) and specs from [ToolRegistry.swift](../../Packages/OsaurusCore/Tools/ToolRegistry.swift). Check [ChatToolChoicePolicy.swift](../../Packages/OsaurusCore/Services/Chat/ChatToolChoicePolicy.swift) for auto/required choice and [ChatView.swift](../../Packages/OsaurusCore/Views/Chat/ChatView.swift) for request assembly. [ToolFlowTrueFixTests.swift](../../Packages/OsaurusCore/Tests/Chat/ToolFlowTrueFixTests.swift) covers tool exposure under manual-mode and grant gates; [ChatToolChoicePolicyTests.swift](../../Packages/OsaurusCore/Tests/Chat/ChatToolChoicePolicyTests.swift) covers when intent resolves to required versus automatic choice.

**B. Tools reach the local runtime, but no valid call is emitted.** Follow [ChatEngine.swift](../../Packages/OsaurusCore/Services/Chat/ChatEngine.swift) → [MLXService.swift](../../Packages/OsaurusCore/Services/Inference/MLXService.swift) → [ModelRuntime.swift](../../Packages/OsaurusCore/Services/ModelRuntime.swift) → [MLXBatchAdapter.swift](../../Packages/OsaurusCore/Services/ModelRuntime/MLXBatchAdapter.swift). Parser selection/execution belongs to the pinned upstream vmlx-swift `BatchEngine`; the parser implementation is not in the Osaurus source tree. [MLXServiceRuntimePolicyTests.swift](../../Packages/OsaurusCore/Tests/Service/MLXServiceRuntimePolicyTests.swift) covers bundle tool-support metadata and preflight policy, while [ToolCallProcessorFuzzTests.swift](../../Packages/OsaurusCore/Tests/Service/ToolCallProcessorFuzzTests.swift) exercises the imported parser's prose fidelity and Gemma tool-envelope detection.

**C. Calls are emitted but not transported correctly.** Follow [GenerationEventMapper.swift](../../Packages/OsaurusCore/Services/ModelRuntime/GenerationEventMapper.swift) → [ResponsesGenerationEvent.swift](../../Packages/OsaurusCore/Services/Inference/ResponsesGenerationEvent.swift) → `ChatView.processStreamDeltas` in [ChatView.swift](../../Packages/OsaurusCore/Views/Chat/ChatView.swift). [GenerationEventMapperTests.swift](../../Packages/OsaurusCore/Tests/Service/GenerationEventMapperTests.swift) covers runtime `.toolCall` conversion, argument serialization, progress, and batch bridging; [LocalToolCompletionContractTests.swift](../../Packages/OsaurusCore/Tests/Chat/LocalToolCompletionContractTests.swift) uses a fake tool-capable service to verify completed-call aggregation and response accounting, not real local inference.

**D. Calls reach the application but fail to execute.** Follow ChatView's loop hooks through [AgentToolLoop.swift](../../Packages/OsaurusCore/Services/Chat/AgentToolLoop.swift) to [ToolRegistry.swift](../../Packages/OsaurusCore/Tools/ToolRegistry.swift), including [ToolExecutionScope.swift](../../Packages/OsaurusCore/Tools/ToolExecutionScope.swift) and the relevant permission policy. Use [AgentToolLoopTests.swift](../../Packages/OsaurusCore/Tests/Chat/AgentToolLoopTests.swift), [ToolExecutionSurfaceTests.swift](../../Packages/OsaurusCore/Tests/Tool/ToolExecutionSurfaceTests.swift), and [ToolRegistryAutoApproveTests.swift](../../Packages/OsaurusCore/Tests/Tool/ToolRegistryAutoApproveTests.swift) for loop, execution-surface, and permission-gate contracts.

## UI-only versus shared-contract changes

An appearance-only adjustment can usually stay within the owning SwiftUI view and its shared design primitive. Expand into managers/stores when layout uses persisted window state. Expand into configuration, prompt, tool, provider, and runtime owners when a control changes effective behavior. A change touching a request, streaming event, tool boundary, persistence schema, permission, or inference route is cross-component: follow its full producer-to-consumer path in [DEPENDENCY_MAP.md](DEPENDENCY_MAP.md).
